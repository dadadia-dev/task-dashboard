# 開発計画

## 目的
業務ごとに関連すること（タスク・改善・手順・リンク）を管理し、各業務を効率化する。
「どの業務に何時間使っているか」の集計は主目的にしない。

## 段階
| 段階 | 内容 | 状態 |
|---|---|---|
| 0 | 開発環境の準備（Node.js・Git・VS Code・GitHub・Vercel） | 完了 |
| 1 | Vite＋Reactで雛形作成、棚卸しデータをJSON化して読み込む | 完了 |
| 2 | 業務マップ画面（分類別時間グラフ、属人度×自動化余地のマトリクス） | 完了 |
| 3 | GitHubへpush → Vercelで公開（ダミーデータ版） | 完了 |
| 4 | 業務ポータル（下記） | 未着手 |
| 5 | （任意）Supabaseでデータ保存・ログイン。実データでどこからでも使う | 未着手 |

## 段階4：業務ポータル
- ホーム
  - 業務一覧（分類ごと）。各業務に「未完了タスク数」「改善中の数」を表示
  - 横断ビュー：全業務の未完了タスク・進行中の改善をまとめて見る
  - 属人度×自動化余地のマトリクスは、改善する業務を選ぶ入口として残す（色は時間ではなく件数に）
  - 分類別の時間グラフは外す
- 業務の詳細ページ
  - タスク：その業務のToDo（追加・完了・期限）
  - 改善：アイデアと状態（未着手→対応中→完了）、方法（自動化／委任／テンプレ化／やめる）
  - 手順・メモ：やり方や注意点。引継ぎ用の手順書にもなる
  - リンク：管理画面・スプレッドシートなど、その業務で使うURL
- 保存先はまずブラウザ（localStorage）。毎日使うと決めたら段階5で移行する

## 決めたこと
- 公開版はダミーデータ（固有名詞を伏せた版）。実データは `private/` で手元だけ
- ダミー化は業種は残し、地域・固有名詞を伏せる
